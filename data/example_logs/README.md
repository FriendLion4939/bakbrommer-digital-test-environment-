# Example logs — SYNTHETIC, not measured

These files were **generated by the simulator** (`scripts/make_example_logs.py`).
They are not recordings of the real vehicle. They exist so that import,
replay and calibration can be tried and tested before real logs are available.

| File | Format |
|---|---|
| `example_ride_sd.csv` | CSV as an SD-card logger might write it (50 Hz). Mapping: `data/mappings/example_sd_card.yaml`. |
| `example_ride_can.log` | candump text. Definitions: `data/can/bakbrommer_example.yaml`. |
| `example_ride_savvycan.csv` | The same CAN frames as a SavvyCAN CSV export. |

The simulated "real" vehicle differs from the default profile in four values,
so a calibration has something to find:

| Parameter | Default profile | Value used for the example ride |
|---|---|---|
| `mass.chassis.mass` | 130 kg | 150 kg |
| `tyre.rolling_resistance_scale` | 1.0 | 1.3 |
| `aero.frontal_area` | 1.0 m² | 1.15 m² |
| `battery.internal_resistance` | 60 mΩ | 85 mΩ |

Deliberate flaws for testing the cleaning step: one impossible speed value and
one empty cell in the CSV; a 1.5 s hole in the battery CAN message.

When you have real logs, put them anywhere and import them through the UI.
A profile calibrated on these synthetic files is **not** validated against
reality.
